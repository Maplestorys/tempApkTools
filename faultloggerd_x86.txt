## x86_64 下实现 FP Unwind 需要的修改分析

根据代码分析，当前 ARM64 的 FP unwind 已完整实现，而 x86_64 的 FP unwind 支持缺失。以下是需要的修改：

---

### 1. 问题现状

**当前代码中的关键限制：**

在 `dfx_regs.cpp:203-217` 中，`GetFp()` 和 `SetFp()` 方法只对 ARM、ARM64、RISC-V 和 LoongArch 架构生效：

```cpp
uintptr_t DfxRegs::GetFp() const
{
#if defined(__arm__) || defined(__aarch64__) || defined(__loongarch_lp64)
    return regsData_[REG_FP];
#else
    return 0;  // x86_64 返回 0
#endif
}

void DfxRegs::SetFp(uintptr_t fp)
{
#if defined(__arm__) || defined(__aarch64__)  || defined(__riscv) || defined(__loongarch_lp64)
    regsData_[REG_FP] = fp;
#endif  // x86_64 不执行任何操作
}
```

在 `fp_unwinder.h:117-128` 中，`GetPcFpRegs()` 仅实现了 ARM64 版本的汇编：

```cpp
static inline AT_ALWAYS_INLINE void GetPcFpRegs(void *regs)
{
#if defined(__aarch64__)
    asm volatile(
    "1:\n"
    "adr x12, 1b\n"
    "stp x12, x29, [%[base], #0]\n"
    : [base] "+r"(regs)
    :
    : "x12", "memory");
#endif
}
```

在 `unwinder.cpp:876-905` 中，`FpStep()` 函数仅支持 ARM64：

```cpp
bool Unwinder::Impl::FpStep(uintptr_t& fp, uintptr_t& pc, void *ctx)
{
#if defined(__aarch64__)
    // ARM64 FP unwind 实现完整
    // ...
#endif
    return false;  // x86_64 直接返回 false
}
```

void DfxRegsX86_64::SetFromFpMiniRegs(const uintptr_t* regs, const size_t size)
{
    if (regs == nullptr || size < FP_MINI_REGS_SIZE) {
        return;
    }
    // x86_64 stack layout: [return_addr, rbp, ...]
    regsData_[REG_X86_64_RBP] = regs[0];  // fp
    regsData_[REG_X86_64_RSP] = regs[1];  // sp
    regsData_[REG_X86_64_RIP] = regs[2];  // pc
}

#### 修改 4: `unwinder.cpp` - 在 `FpStep()` 中添加 x86_64 支持

**文件**: `interfaces/innerkits/unwinder/unwinder.cpp:876-905`

**需要修改**：

```cpp
bool Unwinder::Impl::FpStep(uintptr_t& fp, uintptr_t& pc, void *ctx)
{
#if defined(__aarch64__)
    DFXLOGU("+fp: %{public}lx, pc: %{public}lx", (uint64_t)fp, (uint64_t)pc);
    if ((regs_ == nullptr) || (memory_ == nullptr)) {
        DFXLOGE("[%{public}d]: params is nullptr", __LINE__);
        return false;
    }
    if (ctx != nullptr) {
        memory_->SetCtx(ctx);
    }

    uintptr_t prevFp = fp;
    uintptr_t ptr = fp;
    // ARM64: fp 指向 [saved_fp, saved_lr]
    if (ptr != 0 && memory_->Read<uintptr_t>(ptr, &fp, true) &&
        memory_->Read<uintptr_t>(ptr, &pc, false)) {
        if (fp != 0 && fp <= prevFp) {
            DFXLOGU("Illegal or same fp value");
            lastErrorData_.SetAddrAndCode(pc, UNW_ERROR_ILLEGAL_VALUE);
            return false;
        }
        regs_->SetReg(REG_FP, &fp);
        regs_->SetReg(REG_SP, &prevFp);
        regs_->SetPc(StripPac(pc, pacMask_));
        DFXLOGU("-fp: %{public}lx, pc: %{public}lx", (uint64_t)fp, (uint64_t)pc);
        return true;
    }
#elif defined(__x86_64__)
    DFXLOGU("+fp: %{public}lx, pc: %{public}lx", (uint64_t)fp, (uint64_t)pc);
    if ((regs_ == nullptr) || (memory_ == nullptr)) {
        DFXLOGE("[%{public}d]: params is nullptr", __LINE__);
        return false;
    }
    if (ctx != nullptr) {
        memory_->SetCtx(ctx);
    }

    uintptr_t prevFp = fp;
    uintptr_t ptr = fp;
    // x86_64: fp(rbp) 指向 [saved_rbp, return_addr]
    // stack layout: [return_addr, saved_rbp, local_vars...]
    // rbp 指向 saved_rbp，return_addr 在 rbp+8
    if (ptr != 0 && memory_->Read<uintptr_t>(ptr, &fp, true) &&
        memory_->Read<uintptr_t>(ptr + 8, &pc, false)) {
        if (fp != 0 && fp <= prevFp) {
            DFXLOGU("Illegal or same fp value");
            lastErrorData_.SetAddrAndCode(pc, UNW_ERROR_ILLEGAL_VALUE);
            return false;
        }
        regs_->SetFp(fp);
        regs_->SetSp(prevFp);
        regs_->SetPc(pc);
        DFXLOGU("-fp: %{public}lx, pc: %{public}lx", (uint64_t)fp, (uint64_t)pc);
        return true;
    }
#endif
    return false;
}
```

### 3. x86_64 FP Unwind 栈帧布局

```
x86_64 典型栈帧布局（使用 RBP 作为帧指针）:

+------------------+  <- 当前 RBP
|  保存的 RBP     |  [RBP] 指向这里
+------------------+
|  返回地址 (RA)  |  [RBP + 8]
+------------------+
|  本地变量       |
|  ...            |
+------------------+
|  参数 (如适用)   |
+------------------+  <- 当前 RSP
```

FP Unwind 逻辑：
1. 从 `RBP` 读取保存的 RBP → 新的 FP
2. 从 `RBP + 8` 读取返回地址 → 新的 PC
